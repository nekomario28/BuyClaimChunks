# 価格設定変更と購入台帳

BuyClaimChunks Continuedは、成功した購入で実際に消費したアイテム数をサーバー側へ記録します。これにより、あとから価格曲線を変更しても、プレイヤーが既に所有している土地やclaim枠を没収せずに調整できます。

## 保存する値

ワールドの`SavedData`へ、プレイヤーUUIDごとに次を保存します。

```text
通貨アイテムの登録ID
本MODで購入したclaim枠数
累計消費アイテム数
台帳schema version
```

現在の追加claim上限の正本は引き続きFTB ChunksまたはOpenPACです。BuyClaimChunksの台帳は、本MODの購入による経済的な由来だけを記録します。

## 値上げした場合

既存claimは減らしません。

値上げ後の次回購入額は、次の式で計算します。

```text
次回支払額
= 新しい曲線で今回購入後の有料枠数までに必要な累計額
- これまで実際に消費した累計額
```

例：

```text
購入済み2枠
累計消費：ダイヤ2個
新しい価格：1枠4個の固定価格
2枠までの新しい累計価格：8個
繰越不足額：6個
3枠目の通常価格：4個
次回購入価格：10個
```

既存の2枠はそのまま維持され、不足している6個は次のclaim枠を買うときだけ回収されます。

## 値下げした場合

過去の支払い額で、新しい曲線ならより多くの枠を買える場合、その差分を補償creditとして扱います。

次に`/buyclaim`が成功するとき、補償枠を指定した購入分より先に付与します。1コマンドで付与する合計枠数は、指定購入分を含めて`maxPurchaseAmount`以内にし、backend総枠数も`maxExtraClaims`以内にします。一度に付与できないcreditは累計支払いとして残り、後続の枠が無料または安価になります。

例：

```text
購入済み2枠
累計消費：ダイヤ12個
新しい価格：1枠4個の固定価格
12個なら3枠相当
次の /buyclaim で補償1枠を追加
さらに指定した1枠をダイヤ4個で購入
```

## 通貨アイテムを変更した場合

`amountRequired`、`priceGrowthFactor`、`priceExponent`だけを変更した場合は、同じ通貨の実際の支払い履歴を維持し、値上げ不足額または値下げcreditを計算します。

`itemRequired`自体を変更した場合、ダイヤと他MODのコインなどの交換比率は自動判断できません。そのため通貨変更時は、購入済み枠数を維持したまま、新しい曲線で新しい基準額を作ります。異なるアイテム間の自動的な負債・credit変換は行いません。

## 旧バージョンからの移行

購入台帳導入前のバージョンは累計消費数を保存していません。アップグレード後に初めて利用した時点で、backendが報告する現在の追加枠数を、その時点の価格曲線で既に購入済みだったものとして基準化します。

これにより次の購入価格は従来どおりになり、その後から正確な消費数追跡が始まります。ただし旧データでは、購入枠と管理者が無料付与した枠を区別できないため、アップグレード直後に価格を大きく変更する場合は特殊なプレイヤーを確認してください。

## 安全な取引順序

1. backendの現在枠と購入台帳を読みます。
2. 値上げ不足額または値下げcreditを計算します。
3. インベントリの支払いを確認します。
4. backendの枠を更新し、再読込して確認します。
5. 引用時点の台帳と一致する場合だけ新しい台帳値へ更新します。
6. 支払いを消費します。
7. 支払いが想定外に失敗した場合、backend枠と台帳の両方を元へ戻します。

拒否された取引ではアイテムを消費しません。
